# 按模拟帧提交地图块

开启 `SHINY_STREAMING` 后，房间可读取离线工具生成的 32×32 地图块。
索引格式为 3，每项包含坐标、文件名和准确字节数；旧格式明确拒绝。
玩家/相机区域的请求与引用管理可使用 [Lua 关注区域模块](stream-regions.md)。
已发布的图块层可使用 [流式图块模块](stream-tiles.md)准备并绘制。

```lua
return {
    init = function()
        sc.stream.open("built/map-world/index.json")
        sc.stream.request(0, -1, 0) -- 第一次 update 前必须可用
        sc.stream.request(1, -1, 120) -- 提前读取，在第 120 帧开放
    end,
    update = function()
        local chunk = sc.stream.get(0, -1)
        -- chunk.layers 为图块数据，chunk.objects 为对象；由游戏接入世界。
        if sc.tick() == 120 then
            local next_chunk = sc.stream.get(1, -1)
        end
    end,
}
```

`request(x, y, commit_frame)` 返回递增请求序号并增加引用计数。新请求的计划
帧按请求顺序不递减；update 内只能请求未来帧，初始化可请求第 0 帧。重复
请求尚未提交的块必须使用原计划帧；已活动块的重复请求仅增加引用计数。
索引中不存在的稀疏区域已知为空，序号为 0，不需要读取或等待。

`get(x, y)` 不等待磁盘。已请求但未提交时返回 `nil`；提交后返回数据副本。
即使后台已读完，计划帧之前也不可见。未请求的非空块会报错。`get` 仅允许
init/update；draw 使用游戏已准备的表现数据，避免改变缓存访问顺序。

## 提交与等待

应用拥有一个按需启动的后台线程，只负责读取、解码和校验；活动房间与候选房间
共用它，各自保留独立缓存、引用和提交队列。任务持有文件路径及校验数据，
不借用房间、世界或 Lua 对象。主线程在每次固定 update 前预检所有
到期请求；整批就绪后按请求顺序发布。后请求的缓存数据不能越过较慢的前序
请求。任一到期请求失败时，保留原有可见集合，不部分发布新批次。

到期但未就绪时，宿主暂缓玩法更新、物理、模拟帧号、回放消费及逐帧 trace。
图形端继续绘制、窗口事件与设备采样、音频设备维护；等待时间不累积为补帧。
键鼠/手柄边沿由现有有界输入缓冲累积，回放和录制仍以真正消费的模拟帧为准。
无窗口端每次未就绪后短暂让出 CPU；这段等待计入 profile 的等待时间。

块失败时，图形端显示错误并保持当前画面及模拟状态；UI 可读取失败并重试。
无窗口默认返回带请求序号的 `stream` 诊断；若场景声明 ui_update，则先提供一次
dt=0 的处理机会，必须立即调用 retry 或退出，否则仍返回原错误，避免无声等待。

## 失败与重试

`sc.stream.failure()` 返回独立记录 `{sequence, frame, x, y, message}` 或 nil。
只报告主线程在计划边界观察到的首个失败，不提前泄露后台读取/校验结果。
frame 为原计划帧，x/y 为块坐标；draw/ui_update 可以读取，读取不改变 LRU。

`sc.stream.retry(sequence)` 只重试当前失败请求，返回 true；错误序号、重复重试、
数字字符串和多余参数报错。允许 load/init/update/ui_update，禁止 draw。
它保留原请求序号、提交帧、引用、内存预留和 pending 区域，只重新排入后台读取；
不会阻塞等待，不释放旧世界或加载边界，也不把坏块当作空地。成功后仍整批发布。
排队成功清除 failure；再次读取失败会在同一边界重新报告，游戏决定是否再次尝试。

实时 UI 可以将按钮回调直接绑定到 retry，或显式处理 Enter：

```lua
ui_update=function(dt)
    Input.update(actions, 'ui')
    local failure=sc.stream.failure()
    if failure then
        Input.consume_sources(actions, {all=true})
        if sc.input.key_pressed('enter') then sc.stream.retry(failure.sequence) end
        -- draw 中展示 failure.message；也可提供调用 sc.app.quit 的退出按钮。
    end
end
```

这里的 Input/actions 沿用[命名动作](input-actions.md)，在 gameplay update 中用
同一对象接收消费结果。重试不会修复内容本身：缺文件、坏 JSON、错误坐标或字节数
需由开发流程/外部存储修复；索引不会在重试时重载。多项失败按原请求顺序逐项报告。
普通输入回放仍按模拟帧推进，停等时不会消费未来的重试按键；故障自动测试显式
协调文件修复与 UI 重试，不把磁盘故障到达时刻视为离线输入回放的一部分。

## 预算与释放

默认缓存预算 128 MiB；原生接口可设为 64 KiB..128 MiB。索引上限 16 MiB、
65536 个非空块；最多 1024 个待提交请求。块文件最大 2 MiB，每块最多 64 层，
每层固定 1024 个无符号 32 位 GID。坐标范围为每轴 -31250..31250 个块。

每块另含 `objects` 数组，最多 4096 个对象；没有图块的对象区域也生成块。
索引保留地图/组/图层属性与图集元数据，不集中存放对象。组与子层以一基索引
关联；详见[地图属性契约](tiled-map-properties.md)。对象坐标包含组和对象层偏移，仍为
全局像素坐标；按锚点 `floor(x / (tilewidth * 32))`、y 同理分配唯一归属块。
跨块矩形或多边形不复制对象；其覆盖区域的关注与碰撞接入仍待世界层实现。
对象锚点限制在每轴正负一百万图块的范围内。

对象模板在离线构建时展开，属性继承、图块 GID 与文件依赖的规则见
[模板导入](tiled-templates.md)。运行时不再读取模板。

对象的 `layer` 是索引中图层数组的零基序号，`persistent_id` 为
`组路径/层名:Tiled对象ID`。离线工具检查 ID 格式及全图重复；层路径须满足
[对象持久 ID](identity.md) 的 ASCII 规则，对象显示名称不受此限制。
移动对象不改变 ID，重命名层路径会改变 ID。后台读取校验块内 ID 唯一性、
所属对象层、坐标及归属块；错误阻止整批发布。它不会为此读取其他块，
跨块重复 ID 由离线构建检查。已知空区域返回空 `layers` 和 `objects`。

按索引字节数的 64 倍保守预留解码存储，申请不足即报错，不等后台完成后再
决定容量是否够用。LRU 淘汰由主线程执行，仅选择无引用、无待提交请求的块。
`stats()` 的 `resident_bytes` 包含已预留存储，`loaded` 指已提交且仍有引用的
块，`queued` 指待提交请求；这些计数不泄露后台完成时机。

`release(x,y)` 释放一个引用；最后一个引用释放后立即不可见。已提交给读取器的
请求仍在读完后的原定边界收尾并归还预留预算。
收尾前拒绝重新请求该块，避免旧任务影响新请求；引用计数不平衡会报错。

销毁房间则直接取消所有任务，不等待文件读取：尚未开始的任务移出队列，已开始
的任务完成后丢弃结果，不会写回新房间。加载器最多持有 2049 个地图任务（两个房间
各 1024 个请求，加一个取消后仍在读取的任务）。取消中的单次读取临时内存可能
短暂超出存活房间的缓存统计；线程不额外复制整个索引或世界。
仅应用退出时等待线程结束，操作系统中已经开始的文件读取不能被本接口中断。
原生独立使用 `ScStream(path,budget,reader)` 会自有加载器，销毁时仍等待线程；
需共享应用生命周期时使用 `ScStream(path,loader,budget)`，加载器必须晚于房间销毁。

## 图片读取基础

应用持有的 `ScContentLoader` 在同一个 FIFO 工作线程上提供原生 PNG 请求，
不调用 raylib、Lua 或 GPU。`submit_image({path,width,height})` 复制/接管请求，
`take_image(ticket)` 非阻塞查询并一次性移交 RGBA8 像素；未完成或短暂锁竞争返回
空值，读取错误返回 expected 错误，过期/错误类型的票据拒绝使用。
该原生票据不是 Lua 接口或模拟帧发布事件，消费者仍须在确定边界准备并提交资源。

最多 128 个未取走的图片任务，按声明的 `width*height*4` 合计预留 128 MiB，
包括排队、解码中和已完成但未取走的结果。尺寸为 1..8192，编码文件最多 32 MiB；
实际 PNG 尺寸必须与请求一致。支持 PNG 的调色板/透明度等标准像素类型，统一输出
RGBA8。独立固定的 stb_image 实现只启用 PNG，解析工作内存另限 256 MiB；
输入缓存、分配器元数据及返回像素不计入该解析预算，不能将其当作进程峰值。

取消尚未开始的任务立即移出队列；正在解码的任务先释放结果，再归还预留字节。
取走结果后，像素所有权与驻留预算责任转交调用者。已取走结果可独立于加载器存活。
PNG 解码及依赖仅随 `SHINY_STREAMING` 启用，不要求图形上下文；默认轻量构建不引入
这份独立解码器。[原生图片缓存](image-residency.md)已提供引用计数、CPU 淘汰和
主线程 GPU 上传适配器；宿主/Lua 的 `sc.images` 显式准备事务已接入固定帧等待，
声明 `stream=true` 的图片可按需加载；流式世界模块的 residency 选项管理块/对象的
图片依赖，准备后联合发布，Wayfarer 已接入。

## 尚未接入

原生读取器发布已校验的块数据。[流式世界模块](stream-world.md)已协调图块绘制、
物理/导航、加载边界、对象重建与卸载保存；开启 residency 后，图片也随世界事务
准备并提交。默认资源仍预载，候选房间自身的异步初始化尚未完成。宿主的独立 [`ui_update`](ui-lifecycle.md) 在等待期间更新界面，
命名动作消费与加载失败重试已接入。宿主已提供[异步存档事务](chunk-saves.md)，
流式世界模块已异步读取进入块状态、准备新区域，再异步保存离开块，完成后联合发布；
任一阶段失败保留旧世界，提供按阶段重试与取消。首次加载也等待读取结果后发布。
应用级命名网络会话已由宿主持续维护，并在恢复固定更新时有界交付事件，详见
[网络契约](networking.md)。本地 Lua 会话仍依赖脚本主动轮询。索引打开仍是
同步操作，应用退出仍等待正在进行的读取；房间销毁已不再等待磁盘。
本功能不等于规定的流式地图性能验收通过。
