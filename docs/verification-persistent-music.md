# 持久音乐取得与跨房间复用（2026-09-27）

`sc.audio.music(resource, options?)` 复用应用中同资源路径的活动持久音乐声部，
不重置句柄/播放位置；没有匹配时才按已有声部容量和优先级规则创建。沿用应用
音频草稿和设备所有权，不增加注册表、服务容器或存档字段。只复用未停止中的
持久声部，重复显式播放的声部不会被隐式合并。

已执行必要检查：

- 新无窗口集成：同路径别名、重复取得、非法补丁原子拒绝、容量不足、调用阶段、
  跨房间句柄及连续播放位置、只保存普通进度；Release 与 ASan/UBSan 通过。
- 音频契约检查扩展至新函数和 ScMusicOptions，Release 与 ASan/UBSan 通过。
- 八帧隐藏/静音宿主检查：失败候选房间通过新接口取得/修改/停止音乐后报错，
  活动房间音乐和音量不受影响；成功候选复用原声部并连续推进八帧位置。
- Crossing 原有三关回放、存档恢复、机关和重开检查通过。逐帧 trace 额外确认
  三关只有一个主题音乐声部且 ID 不变。样例未将运行时句柄存入共享状态或存档。
- full 与全功能无窗口 sanitizer 相关目标构建成功；注解/参考文档一致性通过，
  14 份示例注解同步，8 个 SDK 清单审计通过，更新 SDK 为 dev.31。

原生入口只保留指针、标量及平凡 voice 副本跨 Lua API 调用；选项读取的 C++
所有权仍在错误转换前释放。复用分支不引入跨 Lua longjmp 的 RAII 对象。

未打开音频设备或扬声器。逻辑位置连续、静音设备路径及候选回滚，不等于已经
验证真实硬件无缝播放；音质、听感、驱动以及不同平台仍未验收。此项没有画面改动，
未重复已有截图或进行性能/压力测试。
