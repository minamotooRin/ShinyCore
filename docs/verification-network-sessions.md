# 应用网络会话验证 · 2026-09-23

命名会话由应用持续维护，使用固定 256 事件 FIFO；Lua 每次固定更新最多读取
64 个事件，发送上限为 64 次调用和 64 KiB 负载。队列超限明确关闭该传输，
保留故障记录，允许检查后显式关闭绑定。完整语义见 [网络契约](networking.md)。

## 实际验证

Windows 本机 UDP 回环，Release 使用现有 GNU 工具链；无窗口检测使用
LLVM-MinGW 22.1.8，启用 ASan/UBSan 与遇错退出。

- `tests/test_net.cpp`：没有模拟更新时仍收包；固定更新前不可读；64 事件
  交付边界；可靠事件顺序与环形回绕；消息/字节发送预算及下帧恢复；
  256 事件积压后的明确故障、端口释放。
- `tests/test_net_lua.cpp`：stats 字段、终止后的错误读取及显式关闭，原有
  分配失败、GC、失效绑定与 VM 清理检查继续通过。
- `tests/network_integration.py`：5 项真实双进程测试通过。新增测试在模拟
  暂停时连接，跨房间保留端口和 peer，候选 init 拒绝 poll，并在新房间完成
  双向握手。原有 DUET 权威状态、非法消息及输入过期检查继续通过。
- `build/full` 全部 24 项 CTest 通过；网络关闭的 `build-dev` 全部 19 项通过。
- `build-llvm-sanitizers` 无窗口 ASan/UBSan 全部 24 项 CTest 通过。

## 尚未验收

本次证明应用会话维护、积压约束和跨 VM 生命周期，不是完整联机验收。
没有四人玩法、30 秒重连令牌、弱网代理或持续两小时联网记录。停止模拟的
服务路径以原生不调用 begin_tick 的测试覆盖；未增加实际磁盘延迟期间的
双进程图形测试。原生网络仍在宿主线程处理，本地非命名会话依赖 Lua poll。
Linux/macOS 本轮未运行；不沿用旧版平台报告作为当前变更证据。
