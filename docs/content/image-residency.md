# 图片驻留与显式准备

开启 `SHINY_STREAMING` 后，项目可将 PNG 声明为
`resources.forest={type="image",path="forest.png",stream=true}`。
默认 `stream=false`，沿用房间加载时的资源准备。`sc.images.available` 表示能力；
关闭模块时不注册其他 `sc.images` 函数，也不引入独立 PNG 解码器。

## 房间初始图片

```lua
return {
    preload_images = {"forest", "hero"},
    init = function() sc.spawn{sprite="hero", x=32, y=32} end,
    draw = function() sc.image("forest", 0, 0, 320, 180) end,
}
```

`scene.preload_images` 默认不指定，提供时需要 streaming 模块；最多 128 个不同
资源名或已声明路径。与 `sc.images.prepare` 共用名称解析、容量和法线依赖规则。
列表在场景加载时复制，init 可配置法线绑定。init 完成后宿主准备并自动提交初始
图片集合，再执行首次 draw 和资源预检；游戏不持有该准备请求号。
之后调用 `sc.images.prepare` 仍替换整个集合，必须包含需要继续使用的初始图片。

切房间及 F5 复用同一候选流程：后台解码、每个宿主帧有界上传，等待期间旧房间
仍绘制并接收 UI 更新，设备和网络服务继续运行；固定模拟、回放输入不前进。
首次 draw、资源及静默音频准备全部成功才替换旧房间。候选状态/音频仍隔离，
候选 init 禁止存档写入和网络修改。失败释放候选引用，图形宿主显示错误并保留
旧房间；无窗口直接失败退出。F5 不重读已缓存的流式 PNG，重读使用显式 reload。

触发切换的固定帧在候选成功/失败后才输出 trace、通知调试器；等待次数不产生
额外记录。即使达到 `--frames`，也先完成已触发的切换。初次启动尚无活动房间时，
原生窗口显示简易加载提示。`--check-all` 同样准备初始图片并检查各房间首次绘制。

## Lua 事务

```lua
local request, visible
return {
    update = function()
        if not request and not visible then
            request = sc.images.prepare({"forest"})
        elseif request and sc.images.status(request).status == "ready" then
            sc.images.commit(request)
            request, visible = nil, true
        end
    end,
    draw = function()
        if visible then sc.image("forest", 0, 0, 320, 180) end
    end,
}
```

`prepare` 接受最多 128 个不重复资源名或已声明的路径（优先按名称匹配），表示**替换房间的整个流式图片集合**，
不是追加；空数组卸载整个集合。只能在活动房间的 `update` 调用，候选加载、
`init`、`draw`、内容检查和已有切房间请求均不允许。一次仅有一个图片事务。
常驻图片只验证声明，不进入缓存；名称和路径指向同一声明时合并，绑定法线图也
加入候选依赖。status.count 是最终流式资源声明数，不含常驻图片。容量预检失败
回退新引用，不影响当前图片。

下一固定帧边界按请求顺序观察后台读取，全部解码后在主线程逐次上传。
未准备完毕时保留固定帧、输入回放位置和当前图片，界面、设备和网络仍更新。
`status` 只返回宿主已观察到的 pending/ready/failed 状态；准备成功后由游戏在
`update` 显式 `commit`，才替换图片引用。需要配合世界变更时，游戏在同次更新
提交已预检的对象/地形，并停止绘制移出集合的图片。

失败信息在 `status(request).error`。游戏可在 `ui_update` 调用 `retry` 或
`cancel`；重试保留请求 ID 和旧图片，取消释放候选引用、解除等待。
无窗口失败只提供一次 UI 恢复机会，未处理即返回错误，避免无人值守死等。
请求 ID 最多 52 位，提交、取消或退出房间后失效，不可写入存档。
未结束的图片事务阻止切房间、F5 重载和存档恢复；存档写入不替换房间，可并存。

`sc.image`、活动精灵、图块、弹体和粒子使用的流式图片必须已提交。
法线贴图绑定可引用流式图片；绘制对应世界表面时，颜色图和法线图都必须就绪。
声明不等于驻留，未使用的图片不自动解码。`--check-all` 仍完整解码所有声明 PNG，
含未使用图片；该命令允许阻塞，不是主循环路径。

## 显式重载

`sc.images.reload()` 在 active update 中重读当前已提交的全部流式图片，返回相同
事务体系的请求号；`status`、`commit`、`retry`、`cancel` 的阶段和语义不变。
没有活动流式图片或已有事务时失败。常驻图片不在此接口范围，F5 不自动调用它。
不监听文件变化，也不在 draw 中同步重读。

重载为同一文件建立未发布的新版本；成功解码并上传仍不影响旧图，只有 commit
将新版本设为后续 acquire 的首选。取消/失败不会污染缓存查找；原有房间持有的
旧版本在最后一个引用释放后才销毁。文件尺寸必须与项目声明相同，改变尺寸需要
重新加载项目/房间声明。损坏、丢失或尺寸变化保留当前有效图片。

旧图与新图共同使用现有容量及字节预算，因此满载缓存可能无法重载；预留失败
明确返回错误，不能为重载提前卸载当前图片。别名共享一份新像素和纹理。
私有的取消版本及不再引用的旧版本立即退出 CPU 缓存，GPU 在下次收集时释放。
若有多个原生所有者仍保留旧引用，它们继续看到旧像素，不被全局指针替换。

使用流式世界时调用 `World.reload_images(world)`，由 owner 管理请求、暂停和恢复，
通过 reloaded 事件确认提交；不要绕过 owner 调用 sc.images。地图、对象和存档
不因图片重载而重建或写入。

## 所有权与预算

应用拥有 `ScContentLoader` 和 `ScImageCache`，每个房间的 `ScRoomImages` 保留
活动与候选引用。图形后端的 `ScGpuImages` 借用同一缓存。销毁顺序为 GPU 适配器、
房间引用、CPU 缓存、加载器；GPU 资源在关闭图形上下文前释放。

CPU 缓存默认 128 MiB、128 项；原生构造参数支持 64 KiB..128 MiB、1..128 项。
同路径、同尺寸共享数据；有引用的图片不被淘汰，无引用的已完成图片按主线程
最近使用顺序淘汰。最后一个引用释放时取消未完成请求。ID 在缓存中单调分配，
不复用；不跨应用使用。房间销毁取消读取，不等待磁盘；应用关闭才等待工作线程。

`acquire` 预留缓存空间，`poll` 才尝试提交读取。取消后的解码仍占加载器额度时，
新请求保持 pending，额度归还后再排队，不能让磁盘速度决定预留是否成功。
失败保留引用与预留量，`retry` 不改变 ID。`pixels` 借用 CPU 数据，不能跨淘汰使用。
`sc.images.stats()` 的 resident_bytes 包括准备中/失败请求的 RGBA 预留量；
pinned 是有引用的不同图片数，不是引用总数。这些统计不包含 GPU、解析工作区或
仍在后台收尾的已取消图片，不能当作完整进程内存。

PNG 尺寸 1..8192，编码文件最多 32 MiB，解码任务合计预留最多 128 MiB；
解析工作区另限 256 MiB。实现和依赖见 [内容读取](streaming.md)。
GPU 适配器每次默认上传一张，原生参数范围 1..128；这是次数上限，不是毫秒保证。
上传失败保留活动纹理；已成功的部分准备纹理可复用。GPU 缓存回收已被 CPU 淘汰
的纹理，未引用图片不能取用。其 count/bytes 仅统计缓存纹理，不包括其他渲染目标。

## 剩余接入

宿主、Lua、渲染与 `shiny.stream_world` 已接入；Wayfarer 的森林图集和药草精灵
已按块/对象依赖准备，玩家等初始房间精灵仍常驻。流式世界使用方式见
[世界事务](stream-world.md)。候选房间已支持上述声明式流式图片准备。
Lua 加载/init、项目文件和 PNG 头检查、地图索引、常驻资源、音频解码和着色器编译
仍在主线程；尚未实现整个房间加载过程的异步化。这些剩余工作和最终流式世界
性能验收均不能由当前图片事务检查替代。
