# 重连生命周期基础验证 · 2026-09-23

后续已用命名会话状态替代 sc.state 携带协议记录，见
[协议状态隔离验证](session-state.md)。以下保留本阶段的验证范围。

新增固定更新边界采样的 `sc.net.time()` 与普通 Lua 模块 `shiny.rejoin`。
记录受容量约束；旧 peer 的重复断开不能延长 30 秒保留期限；令牌匹配才能
恢复原玩家 ID。房间重建显式校验并复制协议状态，套接字仍归应用所有。

## 覆盖范围

- 原生 Lua 绑定：更新边界之间时钟保持不变，下一更新包含真实等待时间，
  新 VM 继续读取同一应用时钟；网络服务调用不单独推进公开时钟。
- Lua 规则：容量不足、重复占位、拒绝接管活动玩家、错误令牌、过期令牌、
  29.999 秒内恢复与恰好 30 秒拒绝、陈旧 disconnect、清理后分配新玩家 ID。
- 状态校验：版本不符、重复玩家/令牌/peer、缺失槽位、期限异常；副本操作
  不改变原记录，时间回退与 NaN 拒绝。
- 两个真实原生进程：初次加入后主动断开，主机切换房间，客户端更换连接；
  错误令牌先被拒绝，原令牌随后恢复原玩家 ID，新的主机端 peer ID 不同。
  新房间的网络时钟没有回退。

脚本为 `tests/rejoin_integration.py`，已加入 CTest；关闭网络时仍运行纯 Lua
规则测试，明确跳过真实联网子测试。API 注解及示例副本已同步。

Windows 本机完整回归：GNU Release `build/full` 27/27；网络关闭的
`build-dev` 22/22；LLVM-MinGW 22.1.8 无窗口 ASan/UBSan 27/27，均通过。
没有修改下载缓存内的依赖或升级第三方版本。

## 交付边界

30 秒精确边界使用注入时间验证，未等待真实 30 秒；实际双进程验证为短时间
断开重连。固定令牌只用于测试，正式主机令牌签发尚未接入。没有以这组检查
宣称四人协作玩法、弱网重连、心跳协议或加密/账号认证完成。

当前使用 sc.state 携带的协议记录不能与检查点自动存档直接组合；专用应用
临时协议状态存储仍待实现。Linux/macOS、两小时联网和真实设备本轮未验收。
