本次改动：

- 候选目标用预分配查询标记去重，替代逐弹体收集、排序和 unique。标记溢出
  时清空后重新计数。每帧复制紧凑碰撞目标数据，避免热循环读取完整实体结构。

  Lua 分配调用附近仅保留借用指针、引用和简单值，避免 longjmp 跳过析构。
- 创建次序用预分配的前后索引维护，密集删除时修复搬移槽位。绘制列表只需
  线性重建，不再在每次增删后对全部弹体排序。未重排透明绘制以换取合批。

## 同日补充：直接批量边界

Lua spawn 改为直接读取严格类型的普通表到初始化时预分配的缓冲区，不再
构造通用 ScValue/map 树或每批原生临时向量。批次数量受已分配容量约束；
空批次返回空表，大批次不再受到存档数据 256 KiB 上限的误限制。
原生 `spawn_batch` 返回连续 ID 区间起点；Lua 完成全部结果表分配后才调用
原子提交，因此 VM 内存不足也不会留下已生成却无法取得句柄的弹体。

- 新增 4096 项完整参数批次、空数组、稀疏/混合数组、元表、错误类型、非有限
  数、未知字段和未登记图集索引的检查。失败不消耗 ID，缓冲区可继续复用。
- 使用真正的 Lua 分配器故障注入，让结果数组分配返回 null。确认 LUA_ERRMEM、
  活动数 0、next_id=1；恢复分配器后同批次成功，关闭 VM 后缓冲区及 Lua 内存释放。
- 完整、轻量、ASan/UBSan 的 systems、core、script、features、contracts、
  complete_integration 六项回归通过。
- 短测最终 JSON 和原生截图与未优化基线完全相同。CPU p50 9.02 ms、
  p99 23.33 ms，GPU p99 5.15 ms；CPU 门槛仍失败，不将波动当作性能改进证明。
  证据：`build/full/barrage-direct-spawn-smoke/report.json`。

## 同日补充：空间网格索引缓存

目标网格增加 8192 槽、最多半载的固定哈希缓存，记录每个网格的首个目标。
超过 4096 个非空网格时使用原排序数组查询，不减少空间范围或目标容量。
碰撞仍使用原连续扫掠、去重和稳定结果排序。缓存与地形查询标记在池初始化时
分配，模拟期间不扩容；避免大型内嵌数组增加调用者栈占用。

新增负坐标、同桶不同坐标、空网格、4225 网格触发回退及回退后重建测试。
初次 ASan 运行暴露测试栈溢出，随后将固定缓冲区移出对象内嵌存储。
首次短测 CPU p50 7.33 ms、p99 10.02 ms，GPU p99 2.16 ms，最小活动数
2000 目标、23219 弹体、20727 粒子；实际命中率检查通过。
最终 JSON 与基线相同，1920×1080 截图逐 RGBA 像素相同。
证据：`build/full/barrage-cell-cache-smoke/report.json`。这仅是 2 秒测量，
不替代 30 秒预热、三次 180 秒的正式验收，也不证明统计意义上的加速比例。

固定缓冲区改为初始化分配后，完整、轻量、ASan/UBSan 的六项回归全部通过。
最终短测 CPU p99 9.23 ms、GPU p99 2.19 ms，数量、命中率、内存检查通过，
最终 JSON 与基线截图逐像素保持一致；证据为
`build/full/barrage-cell-heap-smoke/report.json`。正式长测仍待执行。
