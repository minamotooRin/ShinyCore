## 实际结果

Windows Release `build/full` 与 LLVM-MinGW 22.1.8 ASan/UBSan
`build-llvm-sanitizers` 均通过三个 CTest：

| 测试 | 实际覆盖 |
| --- | --- |
| `constellation` | 全部声明房间校验、消息边界校验、一主机三客机完成两间房、主动断开后恢复原身份 |
| `constellation_weak` | 同一游戏经 UDP 代理注入 150 ms RTT、±30 ms 抖动、5% 丢包、3% 重复包；四进程均完成并恢复身份 |
| `constellation_faults` | 实际原生连接发送非法方向输入、连接后不握手、握手后停止输入、超时后等待超过 30 秒再提交旧令牌 |

故障测试最终主机仅保留本地玩家，待握手表为空，非法消息及过期令牌分别被拒绝。
首轮 Release 实测握手超时 3.041 秒、输入超时 5.032 秒；客机断开后 30.272 秒
收到旧令牌拒绝。这是应用时钟实测，不是仅给 Lua 模块注入虚拟时间。
ASan/UBSan 使用遇错退出设置，未报告内存或未定义行为错误。
本记录只声称上述专项测试通过，未将其代替当前完整测试套件。

轻量 `build-dev` 通过契约及 Constellation 测试：明确拒绝缺少 network 的原项目，
独立协议检查可离线运行，四进程部分明确跳过。

`--native --weak` 使用原生主机窗口和三个无窗口客机完成相同目标与重连。
已检查实际截图：第二间房、四个光点、协作进度条和结算文本均正常可见。
截图位于 `build/full/verification-constellation/native-weak/native.png`。
这里只验证主机画面；客机实时插值画面、实体多机器网络和音频听感未做本轮人工验收。

各构建的 `verification-constellation/` 保存四端最终 watch、日志、代理统计、
故障计时；watch 和日志不包含令牌。代理报告必须证明实际发生上下行丢包和重复，
且无队列溢出。随机注入种子不保证操作系统调度及网络到达时间可重放，
四端最终位置也不要求逐位相同。
