# 关节控制验证（2026-09-24）

本轮实现距离、转轴、滑动关节的限位与电机控制、距离关节独立第二锚点、
原子字段补丁及状态读取。契约见[关节控制](../joints.md)。

原生 `test_joint_controls` 分别推进三种关节：正向驱动 120 帧到上限，
反向驱动 120 帧到下限，验证实际位置/角度；距离关节再验证等上下限锁定，
以及关闭驱动和限位后恢复原静止长度。使用 10×10 像素身体、零重力、
最大驱动力/力矩 100，线性限位容差 1 像素，转轴容差 .03 弧度。
这些是功能检查，不是用户指定的 1000 个活动刚体性能验收。

调试中观察到：驱动力 1e6 会明显拉过距离限位；驱动力 100 的滑动关节在名义
24 像素上限附近达到约 24.69 像素。测试与文档明确采用物理求解容差，
不宣称精确硬限位，不在引擎中额外夹取刚体坐标。

原生与 Lua 检查非法范围整批拒绝、读取副本、未知字段、非有限数、错类型、
第二锚点参数错误、销毁后旧句柄、复用槽位、身体重建失效和 draw 阶段拒绝。
相关测试为 `core`、`script`、`contracts`、`features`；API 注解及项目副本同步更新。
Windows Release 完整构建、轻量构建以及 LLVM-MinGW 22.1.8 无窗口 ASan/UBSan
构建分别通过上述 4/4 项。Sanitizer 使用遇错退出设置，未报告内存或未定义行为错误。
本记录不替代完整测试套件或实机图形验收。

后续同日检查发现旧 32 位关节句柄缺少房间号，切房间后可能误指向新关节。
已改为 52 位范围内的房间/生成号/槽位编码。新增 Lua 实际切房间测试：新房间在
同一槽位创建关节，旧 ID 的读取、修改和销毁全部拒绝，新关节仍可正常操作。
原生测试覆盖最大房间号、超范围拒绝及 double 往返不丢精度。
此修复后重新构建完整、轻量及 ASan/UBSan 配置，上述相关测试仍分别 4/4 通过。
