## 实际结果

Windows 本机 GNU 16.1 Release：轻量配置 CTest **19/19**，完整配置和无窗口
配置各 **22/22**。LLVM-MinGW 22.1.8，无窗口 ASan/UBSan、网络/流式开启、
遇错退出：CTest **22/22**。随后对缓存原子替换和 Lua 返回摘要的最终修改，
四种配置各重跑相关测试 **6/6**。生成文档检查与 `git diff --check` 通过。

新增原生测试验证：

- 多块与房间/共享状态一次提交，普通写档保留未修改块，删除块保留上一份备份。
- 第二块写入、备份替换、当前索引替换处注入真实文件系统错误；读取仍得到
  一个完整旧检查点，重试后清理未引用的记录。
- 记录内容损坏或主索引损坏时整体回退；已选快照的单块读取不会混入旧数据。
  两份都损坏时，写入拒绝悄悄丢掉无法读取的世界数据。
- 重复内容复用、同名文件内容不同则保留原文件并选用新文件名、非法引用和
  单块大小限制、无部分预检写入、只回收引擎管理文件。
- 1024 个块记录的读写与反复访问：更新同一块 12 次后，记录数保持 1025
  （1024 当前记录和一份旧修订），未随更新次数增长。

新增五组 Python 集成测试通过实际引擎进程验证：公开元数据、调用阶段、
整批失败、块删除、检查点摘要不泄露完整索引、磁盘选项、跨房间恢复、新进程
读取，以及损坏时共享状态和所有块一起回退。对象按 `persistent_id` 重建，
测试恢复了对象位置和删除标记。

## 原生后台写入组件（2026-09-27）

Windows GNU Release 与全功能无窗口 LLVM ASan/UBSan 均执行
`test_save_chunks --async`，通过。该选择项只运行本次后台写入检查和已有的三个
原子提交失败边界，不运行 1024 条存档记录负载或整套测试。

实际验证：受控后台等待期间 owner 轮询返回 pending；不可重叠提交或丢弃待处理
写入；主索引替换遭遇真实文件系统错误后仍能读取完整旧检查点。移除阻挡后，
再注入一次 C++ 写入异常，得到可重试诊断，最终按原请求及冻结数据恢复成功。
提交后修改调用方对象没有影响写盘内容；成功结果稳定，释放后旧号失效，后续
检查点保留未修改块。未观察结果便销毁应用写入器，也会完成已经接受的写入。
非法块键和超过 1 MiB 编码负载在排队前拒绝，不修改存档。

同步和异步路径共用块修改预检与格式 3 原子提交实现。完整 Release 与
ASan/UBSan 引擎已重新链接；Lua API、SDK 注解和游戏路径未变，尚不能由游戏
使用这项后台服务。没有启动图形窗口，也没有执行平台、断电、压力或耐久验收。

## 批量异步读取 · 2026-09-27

原有写入器扩展为 `ScSaveIo`，共用一条线程和一个事务槽；原文件已替换，
不保留第二套后台服务。Lua 新增 read_chunks_async/result，status 增加 operation。
读取选取完整有效索引或复用已固定索引，成功 release 后固定选择供后续读取。

Windows Release 与全功能无窗口 LLVM ASan/UBSan 均通过：

- `test_save_chunks --async`：受控读取闸门证明主线程观察不等磁盘、工作线程
  使用请求副本，异常可重试；真实未请求块损坏选择整份备份；修复主文件后仍保留
  选定旧快照；选定块损坏报错而不混入新版，修复后重试；缺失槽、非法/重复键、
  1 MiB 批量结果预算；同时保留原有异步写入及原子失败边界检查。
- `save_read_async.py`：真实宿主固定边界 pending/complete、keys 和结果副本、
  读取不修改 sc.state、摘要/缺失键/缺失槽/空数组、读写及切房间互斥、参数和
  调用阶段、备份恢复、失败时 UI 释放后继续旧世界、无人处理则报错退出。
- `save_async.py` 与 `save_contracts.py`：已有写入、UI 重试、退出完成、缓存与契约
  行为仍通过。未运行整套测试、1024 记录负载或耐久检查。
