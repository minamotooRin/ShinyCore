# 临时令牌签发验证 · 2026-09-23

`sc.net.token()` 通过平台随机源获取 16 字节，返回 32 个小写十六进制字符。
操作系统细节集中在 `src/platform/net_token.cpp`，命名会话所属应用限制每次
固定更新最多 64 次尝试；成功与失败都计入预算。错误返回 nil,error，无时间戳、
玩法随机数或弱随机回退。接口及官方平台说明见 [重连契约](../../network/rejoining.md)。

## 实际证据

- Windows GNU Release 与 LLVM-MinGW 22.1.8 ASan/UBSan：真实平台生成结果
  的长度/字符格式、终止字节，以及本次 64 个样本无重复；这不是随机质量证明。
- 第 65 次调用拒绝，网络 service 不重置预算，下个固定更新恢复。原生注入
  随机源错误验证失败传播，Lua 返回 nil,error，且失败仍扣除一次预算。
- 相同 seed 的两个独立游戏运行，增加令牌调用前后，玩法随机数 watch 与
  世界 hash 相同；令牌不进入玩法随机序列。
- 双进程测试已改用真实签发令牌。错误令牌由正确值修改一位构造，确保不同；
  拒绝后使用原令牌在主机新房间恢复原玩家 ID。
- 候选初始化、draw 和 --check 均拒绝签发；--check 也拒绝 host/join，
  修复了之前检查模式缺少统一网络副作用保护的问题。
- `objdump -p` 检查：完整构建导入 bcrypt.dll 的 BCryptGenRandom，网络关闭
  构建无该导入；没有新增第三方下载或发行时 Python 依赖。

网络关闭构建的契约、重连模块和项目工具 3/3 通过。网络启用的原生 net、
Lua 绑定、契约、重连、四进程弱网及双进程网络测试均执行通过；最终检查模式
保护另行重建并运行相关回归。测试记录区分实际执行的集合，不宣称全平台验收。
最终相关回归：GNU Release 6/6、ASan/UBSan 6/6 通过。Windows 导入表证据保存
在 `build/verification-net-tokens-2026-09-23/`。

## 尚未验收

Linux/macOS 平台实现与构建分支已提供，本轮未在对应系统构建或运行。系统
随机源真实故障没有通过修改操作系统诱发；错误路径使用原生源注入验证。
临时令牌仅用于本会话续接，不建立账号、加密传输或防窃听能力。四人完整玩法、
弱网重连和长期运行仍需整合验收。
