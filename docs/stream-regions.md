# 流式关注区域

`require("shiny.stream_regions")` 为一个房间维护一组块引用。它在原生
`sc.stream` 之上计算关注区域的并集、稳定请求顺序及进入/离开集合。
先在 init 打开流式索引，再创建管理对象：

```lua
local Regions = require("shiny.stream_regions")
local region = Regions.new{tilewidth=8, tileheight=8, margin=1, capacity=256, boundary=true}
-- init 可指定提交帧 0；update 中指定未来帧。
local plan = Regions.request(region, {
    {x=player_x, y=player_y},
    {x=camera_left, y=camera_top, w=320, h=180},
}, commit_frame)
```

矩形使用世界像素坐标与半开边界；w/h 默认为 0，表示点。负坐标向下取整。
`margin` 默认 1，范围 0..8，表示外围预取圈数；`capacity` 默认 256，范围
1..1024，限制并集中的块数。地图图块尺寸必须与索引一致。重叠区域不重复
引用，已有块继续保留；新增块按 x、y 顺序请求同一个计划帧。

`plan.enter/leave` 是进入和离开的 `{x,y}` 数组，供游戏准备对象、地形和绘制。
计划及管理对象除创建参数外均由模块维护，调用者不得修改其内部字段。

- `Regions.ready(region)`：在计划帧及原生发布之前返回 nil；之后一次返回
  全部进入块 `{x,y,chunk}`。它不等待磁盘，不提前暴露已读完的部分块。
- `Regions.commit(region)`：游戏完成世界变更后调用。要求 ready 已成功，
  此时才释放离开区域的块引用，并更新当前区域。
- `Regions.cancel(region)`：释放新增引用，保留原区域。未完成读取的取消请求
  仍按原计划帧收尾；同一块须等该边界后才能重新请求。
- `Regions.contains(region, area)`：检查矩形或点是否完全处于已提交区域。
  可供角色控制器决定是否允许进入；查询本身不修改刚体位置。

同一管理对象同时只允许一个待提交计划。传入空区域数组可请求清空，调用
commit 后释放全部引用。请求失败时释放本次已取得的新增引用，保留原区域；
原生缓存预算须容纳切换期间的新旧块。已知空块同样计入区域容量，但不占
原生块缓存。只有 pending 计划暂存新块数据，管理对象不保留历史块数据。

## 物理加载边界

设置 `boundary=true` 后，commit 为区域外围生成厚 2 像素的透明静态刚体，
阻止动态刚体进入尚未提交的相邻块。默认关闭，纯数据使用不分配实体。
相邻已提交块之间没有墙；不连通区域与区域内空洞分别保留边界。它基于整个
关注区域并集，包括预取圈。块内已有地形仍由地图负责。

边界占用普通实体容量，以 `shiny.loading-boundary` 标签供诊断查询，不持久化。
新边界整批创建成功后才销毁旧边界；容量不足保留旧边界和 pending 计划，
可以处理或取消。预算必须容纳替换时的新旧两批边界。长度超过 4096 像素时
拆段，位置遵守普通实体正负一百万像素的数值限制。无区域变更时复用旧边界。

不要在模块之外删除或修改边界实体。它们使用默认碰撞类别与掩码，故游戏
过滤器必须允许碰撞；高速动态身体应启用 bullet。运动学身体、直接设置位置
和传送不会自动被墙约束，应先使用 contains 检查目标范围。提交区域必须包含
仍活动的角色；本接口不负责将外部角色搬回区域。

## 整合边界

模块管理块引用、覆盖范围及可选物理边界，不自动替游戏创建或销毁玩法对象。可结合
[批量对象加载/卸载](stream-objects.md)使用，但对象、地形与绘制的统一事务
仍待宿主整合；不能把 commit 当作这些世界变更已经成功的证明。
准备失败时不要 commit，保留旧区域并处理或取消计划。若游戏已经修改世界，
cancel 不会回滚这些修改。

才销毁旧墙并释放离开区域的引用。不传 shapes 时保持只提交区域边界的行为。
