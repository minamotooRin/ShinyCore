# Crossing 动画与机关反馈

角色从关卡总时间选帧改为本地标准动画时钟，区分 idle/walk/rise/fall。
松开方向保留朝向；菜单暂停不推进，回营重置。复用 keeper 原有右向帧并显式翻转；
升降帧仍取自原图集，未宣称已具备独立绘制的跳跃美术或最终连续动画品质。

`presentation.lua` 只读取玩法状态。拉杆与信号柱使用未就绪/待操作/完成颜色，
同时配空心/实心菱形与勾号，避免仅依赖颜色。压力板通电后变绿并更新文字。
信号顺序集中在 Campaign.signal_order，游戏规则和表现引用同一份数据。

必要验证与实际观察：

- --check-all 检查三间房；定向原生 Lua 用例覆盖四种角色状态、停步朝向、拉杆
  两光点条件、信号前缀完成和错误操作复位。
- 修改前后各执行一次 2876 帧键盘三关回放。结局、显式存档状态、实体物理快照、
  联系信息、玩法观察、随机数、音频与输入字段相同；视觉字段参与的 hash 不比较。
  这只证明所比较的回放结果，没有声称逐帧所有轨迹或人工游玩时长已验收。
- 磨坊与信号塔从真实回放检查点恢复后，隐藏、静音、限帧捕获并实际查看。
  压力板待操作图标、信号完成勾号、玩家和目标提示可见，没有新标签交叠。
- 一帧原生姿态网格检查四状态的左右朝向及三个机关标记；初版底部标签位置不佳，
  移至屏幕坐标上方后重新查看。最终证据是 poses-final.png，不是 poses.png。
- 依赖闭包含 presentation.lua/campaign.lua/lib/shiny/animation.lua；项目 SDK
  审计通过，标准模块和注解未变，继续使用 dev.46。
